# 本机 Cookie 会话恢复（D04，部分实现）

目标是“已正常登录一次后，重启程序仍能尝试继续读取岗位”，而不是每次重新登录。此改动不声称真实猎聘登录/搜索/详情依赖已经适配；#49 的真实完整 JD 门槛和 #50 的完整登录目标继续保持开放。

## 使用

在 `/guided` 第 2 步勾选“在此工作区本机保留该平台 Cookie 会话”，然后正常搜索。需要登录时仍在平台原生窗口完成登录/扫码/短信/验证；取得可读列表或完成正文采集后，程序才保存本站 Cookie。可与已合并的“登录返回后自动继续”配合。

退出并重新启动工作台后，为新任务再次明确选择本机保留。同一工作区、平台适配版本、后端、浏览器选择、网络策略匹配时，Cookie 在新浏览器打开第一个页面之前恢复。仍正常执行站点规则、配额、TLS 和请求检查；不因恢复失败切身份、网络或重试登录。`restored_session_unverified` / `saved_unverified` 只表示 Cookie 的恢复/保存，不是账号认证证据。实际登录有效性仍取决于平台正常响应。

“停止并关闭登录会话”关闭当前采集浏览器，但保留已明确同意保存的快照。“清除此平台保存的会话并关闭采集浏览器”才删除本工作区该平台快照，并撤销其旧任务的保存选项，不删除岗位、正文、报告、个人证据和配额。其他工作区不受影响。

快照超过七天不再使用，并在下次尝试读取时清理；这不是后台自动删除服务。浏览器仍按 Cookie 本身的过期信息处理会话。网站要求重新验证时必须按正常流程完成。重新登录后可以更新本机快照。

## 保存内容和保护

只保存应用自有浏览器上下文中、平台声明域名下的普通 Cookie；不读取日常浏览器，不读取/存储表单密码，不保存 DOM、截图、localStorage、IndexedDB、sessionStorage、分区 Cookie 或其他平台 Cookie。依赖这些未覆盖存储方式的登录可能无法恢复，不能宣称所有平台都已支持。导出使用浏览器 Cookie API，不创建临时页面、不会为快照发送 HTTP 请求。

文件只位于所选工作区的 `.radar-sessions`，不接受用户指定的任意存储路径。Windows 使用当前用户 DPAPI 加密，不存自建密钥；Linux/macOS 使用 0700 目录与 0600 文件，**不加密**。Base64 只是文件编码，不是加密。快照等价于敏感登录资料，不应分享、提交 Git、同步公共目录或放入数据导入路径；同一系统用户运行的恶意软件仍可能取得登录资料。`.gitignore` 排除该目录，源码打包与输入发现也拒绝其中内容。没有新生产依赖、密码库、云端同步或上传动作。

文件锁由操作系统持有，进程退出后自动释放；第二个进程不能并发恢复/覆盖同平台会话。符号链接、Windows reparse points、硬链接以及宽松的 POSIX 权限被拒绝。写入先生成私有临时文件、刷新后原子替换，避免半写入覆盖有效快照。损坏、解密失败、绑定不匹配都显示固定原因，不输出 Cookie 内容。保存失败不会回滚已经取得的岗位和报告。

## 验证与仍未覆盖

定向测试使用非真实 Cookie，包含跨进程恢复/互斥、过期、损坏、绑定冲突、取消、清除、旧任务撤销、保存失败和无秘密状态返回。完整工作台测试扩展为“正常人工测试登录 → 原报告 → 关闭旧服务/浏览器 → 新服务/新浏览器恢复 → 无新增登录 POST 的正文到报告 → 清除”。四组 native 测试验证恢复的 Cookie 出现在**首个文档请求**，不是进入页面后临时塞入。

上述自动测试均为人工上游，不替代真实招聘站点认证。正常自动表单登录、localStorage/IndexedDB 型会话、平台专用成功/过期判断和真实首条 JD 仍未由本次代码交付。这里没有自动填写密码或绕过平台验证。默认保留关闭，旧任务的内存会话和已有报告路径保持兼容。

## 设计依据

- Playwright Python authentication / storage state: https://playwright.dev/python/docs/auth
- Playwright Browser.new_context storage_state: https://playwright.dev/python/docs/api/class-browser#browser-new-context-option-storage-state
- Windows CryptProtectData: https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata

Cookie 会话状态属于敏感资料；持久化本身不能证明账号仍有效，也不能证明网站允许新的访问。
