# 不整理链接的采集向导：按按钮操作

适用版本：0.2.0。先区分两个窗口：**工作台**负责点按钮、看进度；**采集浏览器**负责打开招聘网站、登录、搜索。不要在原来已登录的 Chrome 标签页操作后，误以为采集浏览器也登录了。

## 已经能打开工作台，就从这里开始

不必更换你的 Python 或 Anaconda。完整取得main源码，停止旧终端，用原来成功的解释器在新源码目录运行：

```bash
/d/code_environment/anaconda_all_css/py312/python.exe scripts/start_workbench.py
```

打开这次终端给出的完整地址，再点击首页的“新手推荐：选平台 → 找岗位 → 勾选采集”。地址会进入 `/guided`。端口每次可能变化。Python 没升级源码不会自动更新；只刷新旧网页不够。

## 第一步：准备浏览器，只做一次

在第1步点“安装 / 修复采集浏览器”，阅读确认框后同意。程序使用启动工作台的**同一 Python**安装 Playwright 和 Chromium，不要求你输入安装命令或换虚拟环境。需要能访问包源和浏览器下载服务；状态为 installed 时再继续。安装失败会提示失败，不会被标成完成；基础页粘贴 JD 的功能不依赖这个安装。

此按钮不会读取你日常浏览器的 Cookie。

## 第二步：告诉程序要找什么

以研究时间序列岗位为例：

| 字段 | 第一次怎么填 |
|---|---|
| 招聘平台 | BOSS直聘，或者你实际使用的猎聘/前程无忧 |
| 分析岗位类别 | 时间序列算法工程师 |
| 搜索关键词 | 时间序列算法工程师；城市筛选可在采集浏览器里手动调整 |
| 最多读取列表页数 | 1 页 |
| 最多采集岗位数量 | 5 个；排障时改1个 |
| 允许使用的依据与用途 | 填实际适用的访问说明/提供方许可和用途；不是另一把 API Key |
| 执行确认 | 核对访问条件后本人勾选 |
| 可选“搜索结果列表地址” | 没有就留空；程序自己构造站内搜索地址 |

点击“打开搜索并读取岗位”。**不要准备职位 URL 清单、搜索 API Key、数据源地址、分页游标或 CSS 选择器。** 它们不是本向导的输入。

若你本来已经有一个搜索结果页面，可展开可选项，把**包含多个职位的列表页**地址粘进去。程序将识别其中真实存在的详情链接，不是让你逐个复制。

只找到0条、看到登录提示或遇到网站改版，不表示一定是填错关键词。继续按下面的提示处理；没有找到的链接不会被编造出来。

## 第三步：要登录，就在采集浏览器里完成

点“打开登录浏览器 / 人工接管”。在弹出的采集浏览器正常完成扫码、短信验证码或登录。网站只提供短信/扫码时，不存在可以靠填密码解决的通用登录方式。

本次版本的账号密码只在招聘网站原生登录页填写，不在工作台托管或自动填写。选择平台网页实际提供的密码、扫码或短信登录方式；必要验证由你本人完成，不自动接受网站条款。

**这里不会自动宣称登录成功。** 请看采集浏览器中的网站实际状态。程序不把账号密码写入任务或证据导出，也不持久化登录 Cookie。停止该任务会关闭会话，退出程序后下次需重新登录。

完成后有两种简单操作：

- 已在采集浏览器打开需要的结果列表：回工作台点“我已打开结果列表：读取当前列表”。
- 只完成登录、还没有搜索：点“登录后重新搜索”。

请勿在采集浏览器里投递简历、发消息、修改个人资料。本工具的自动动作只针对正常登录及只读采集。

## 第四步：勾选岗位，URL 由程序输出

下方显示岗位卡片、列表观察到的真实详情链接和每条状态。勾选需要研究的岗位，或者点“选择本页岗位（不超过上限）”，再点“采集所选并生成报告”。

程序按顺序打开详情、处理允许范围内的导航、保存最终详情地址、提取独立正文、去重入库，调用原分析引擎生成报告。最终跳转地址显示在卡片上；“下载已发现的职位链接”可导出整份观察链接清单。未打开的卡片只有列表观察地址，不能冒充已经验证的最终跳转地址。

本批报告只使用**这次勾选且成功入库的记录**。有报告不代表每个岗位都成功；请看每条卡片的结果。下载“岗位要求 CSV”核对原文，再下载描述模板；本人项目、附件和量化指标仍在高级证据中心编辑。

## 等待时可否关网页？

不要按刷新次数判断是否卡住。默认强制频次（同一工作区、同一平台跨任务/进程共享）：

| 动作 | 硬限制 |
|---|---|
| 页面导航/翻页 | 至少15秒间隔，最多60次/小时、200次/滚动24小时 |
| 经采集后端桥接的 HTTP 请求 | 至少0.5秒间隔，最多600次/小时、3000次/滚动24小时 |
| 打开登录窗口 | 至少5分钟间隔，最多3次/滚动24小时；请复用已打开的登录窗口 |
| 一批列表/详情 | 最多5页列表、20个选中岗位，默认1页/5个 |

页面的脚本、样式、robots 和登录请求也进入 HTTP 台账；一个页面通常不止一个请求，重定向可能消耗额外导航配额。限频中的“等候”不是挂住；界面不能将速度调高。站点的更严限制优先；严格延迟策略暂不兼容时会停止，不默默忽略。

主文档/必要API返回401/403或任何资源返回429时停止，并记录至少5分钟的持久化冷却；429的更长 Retry-After 会保留。可选资源401/403只中断对应请求，不误触发整站冷却。没有自动账号池、代理池或验证码破解。错误后由用户确认是否继续，不无限重试。

已确认批次在本机后台线程执行，**关工作台网页不会停止该批次**。暂停会在当前网络调用结束后停止新动作；停止则关闭采集浏览器。关闭启动终端会停止服务，下次打开显示中断，需重新登录后继续未完成的条目。当前不是开机自启服务，也没有每天定时任务调度器。不要同时启动两份工作台操作同一个任务。

## 看到错误时按这里处理

| 提示 | 含义和下一步 |
|---|---|
| 浏览器组件未就绪 | 点第1步安装/修复；不要更换已经能启动的Python |
| non_public_address / 198.18.* | 点“网络检查”看解析地址。这可能是代理 Fake-IP；先修正DNS/TUN配置。不是缺少登录，不能关闭安全检查来解决 |
| 需要人工操作 | 在程序弹出的浏览器正常登录/验证/搜索，然后读取当前列表 |
| 0个岗位链接 | 页面可能未加载、需要登录或列表结构不兼容。手动打开正确列表后读取；仍为空说明适配需要修正，不编造URL |
| robots_denied / robots_unavailable | 当前路径不满足自动访问条件；转获准接口或基础页的有权处理文本 |
| http_403 / http_429 / cooldown | 停止请求；核对权限/限流，不靠新建任务重置配额 |
| structure_changed | 无法确认独立完整JD，未把整页推荐内容当作正文；可在基础页粘贴完整文本 |
| resource_domain_blocked | 页面资源不在适配器允许域名中，需维护人员审核添加；不要全域名放开 |
| 停止后再继续 | 会话已关闭；需重新登录。已成功岗位保留、不重复入库 |
| 安装失败 | 检查下载网络、磁盘权限；固定安装不会自动绕过企业网络限制 |

## 当前诚实的能力边界

这次新增的是**可执行的 Chromium 采集后端、站点页面适配、列表→真实详情链接→正文的批量链路和登录人工接管**，不是只给一个空抽象类。

但三家招聘平台的登录方式、字段与资源域名会变化，提供的页面适配仍标记 not_live_verified。没有你的实际授权、网络和现场样本，不宣称这三站都已成功登录/抓取。真实浏览器自动测试使用受控的人工站点，它检验人工接管后Cookie复用、动态列表、翻页、跳转、入库和报告，不是招聘平台认证。

也不是“全市场职位穷尽”：卡片来自本次观察到的列表，未知总量时不能算全市场覆盖率。单纯登录不能解决DNS、robots拒绝或页面结构不兼容。

## 合并前回归修复

列表显示后，采集浏览器的后台轮询会冻结，避免你只是在勾选岗位也不断消耗请求；下一次明确操作才恢复。打开登录窗口至少间隔5分钟、滚动24小时最多3次；请复用已打开的原生登录窗口。

正常跳转翻页与不跳转的动态翻页都只扣一次页面动作额度。可选图片/字体/脚本的401/403不会将整个任务误判为登录失败；主文档、必要接口拒绝和任何429仍停下，网络安全检查不放宽。

后面的岗位被阻挡时，前面已经成功的岗位也会生成可下载报告；任务继续显示真正的阻挡原因，不伪装全部完成。自定义站点会将平台配置保存在本批报告里；报告和CLI的版本统一来自同一版本定义。
