# HTTP失败任务转交浏览器：不用重新填写原条件

Refs saksim/vibe_job_radar#3、#9、#23、#27、#30；实现延续PR31。

在高级采集结果中点击“将未完成链接转交浏览器”，先在本机预览。页面显示原授权范围、原HTTP已用/剩余预算、可转交平台和链接。选择后确认一次，即创建并打开对应浏览器任务，沿用原岗位范围与授权依据，只读取所选详情，不重做搜索。需要平台登录时仍由用户在原生页面完成，然后继续既有任务。

原HTTP预算不退款；确认明确授权所选数量（每次1至20条）的额外浏览器正文尝试，仍受原浏览器共享限频和站点访问规则约束。已成功/新鲜复用、尚未执行的预算跳过、明确拒绝、验证码/挑战、限流、证书异常和结果不确定的请求不自动转交。同一主机出现明确拒绝时，不能用该主机其他解析失败条目避开停止条件。

## 已接通的路径

`保存的HTTP任务 → 受本机token与Origin保护的预览 → 快照复核与明确同意 → 既有GuidedService队列 → 详情读取 → 独立本批报告`

预览不打开浏览器、不解析DNS、不请求网站。确认只接受本机任务ID、快照指纹、平台及行号；URL、权限、岗位和失败原因由服务端从已有任务选择，不接受调用方自行指定的URL、Cookie、账号、密钥或新的授权文本。

转交保留父任务ID、原始失败状态、原报告ID、预算快照、确认时间与选中详情。原HTTP记录、额度、私人证据不修改，原客户端的认证头/密钥和诊断原文不拷贝。自由文本授权说明保持原文，不声称可以自动识别其中所有隐私。

每个原任务/平台只有一个持久转交任务；重复确认返回原任务，重启后也不重复执行。不同选项不能覆盖已经创建的任务或重新抓取其成功条目。取消确认不创建任务。原任务变化使未执行的确认失效，必须重新预览。

## 验证和边界

`tests/test_collection_handoff.py` 覆盖离线预览、真SQLite/任务保存、确认、幂等/重启、来源与预算、父状态变化、硬拒绝、敏感字段拒绝、真实本机HTTP鉴权/Origin及受控后台详情/独立报告。

原`run_recovery_browser.py`增加实际Chromium界面流程：预览、取消、确认、定位任务、报告与再次访问复用。数据源是人工夹具，不是招聘站现场采集；原7条浏览器验收脚本不删除。

本项不解决Fake-IP、PAC、跨设备配额、平台真实认证或登录态持久保存。浏览器仍使用原网络/TLS/robots检查，不通过转交放宽限制。删除本地转交文件不是支持的重试办法；如需恢复先保留工作区，继续原任务。
