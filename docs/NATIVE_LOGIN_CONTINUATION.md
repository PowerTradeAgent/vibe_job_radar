# 从正常登录继续原岗位任务

本轮基线：PR36 已合并的 main@36b932e41d6218572134dfa4b162d9d963098eb6。

## 用户流程

在首页选岗位与平台并开始原任务。需要登录时，在程序打开的采集浏览器正常完成登录；回工作台点击 **登录完成，继续原任务**。不重新创建任务、不重新填写关键词，也不上传 Cookie、验证码或密码。

原任务处于搜索阶段时，继续会回到已保存的原搜索地址；处于正文采集阶段时，继续会处理原选择中尚未成功的岗位，保留已经取得的正文和部分报告。按钮点击不等于登录认证成功；站点仍拒绝或要求验证时继续报告实际失败。

“读取当前列表”只适用于当前确实为搜索列表的页面。登录首页、职位详情及其推荐链接不再冒充本次结果。达到页数上限后，重复读取仍检查页面；已见过的同一列表可以确认，新的不同列表仍受原页数上限约束。增加新任务不能重置站点配额。

## 本轮修复的执行问题

- 登录弹窗自关闭后，返回同一浏览器上下文内尚未关闭且属于所选平台的页面，不把仍然有效的会话销毁。未知域名、凭据链接和空白页不作为回退目标；页面选择不会自行导航、清除错误或授权采集。
- 页数达到上限时，不再跳过 snapshot 检查而直接使用旧卡片宣称“准备完成”。当前空列表会明确报告空，不删除已取得内容。
- 列表解析拒绝已知首页/登录页/详情页，验证页路径识别覆盖 captchaPage_ip_PC 等实际观察到的形式；不自动处理或绕过验证。
- 阅读现有页面不清除证书、权限等硬错误；原临时等待处理保持。原生登录开始前记录 manual_pending，即使页面要求人工操作也不丢失继续意图；成功推进后只标记 user_resumed，不声称认证或长期会话已验证。

## 验证与现场边界

新增单测在修复前复现缺陷，修复后与原全量共同执行。新增 scripts/run_native_login_browser.py 用真实工作台和真实采集浏览器验证：初次登录墙→自关闭的原生弹窗→首页推荐拒绝→原搜索→部分正文成功后再次登录→仅继续未完成正文→同批研究报告。上游页面、会话标识、岗位均是人工测试夹具，不是招聘账户或实站认证。保留所有既有浏览器脚本，最新远端结果以对应提交为准。

首轮浏览器CI在最终报告断言发现测试预期错误：两条公司未知、URL不同的人工岗位应保留为两个岗位组，不因正文相同强行合并。已保留原去重模型，修正断言并新增离线回归核对公司为空、正文相同而指纹不同；最终结果以修复后的完整CI为准，未跳过测试。

本轮公开网页检查可读取猎聘的一条详情，另两条进入安全验证页；搜索列表/robots 和本机直接取数没有取得完整成功证据。网页检索工具读取不等于本程序实测成功。没有复制完整第三方正文或员工信息进入代码/测试/证据包，没有反复请求验证页、切换出口或绕过限制。

现场验收仍需在用户自己的有效会话中完成 **一个指定平台、一个目标方向、1页最多5条** 的完整流程。需要补的仅是实际失败阶段和界面错误码，不要提交密码、Cookie 或验证码。主线总控 #3、站点任务 #9、网络任务 #23 继续开放。本轮不新增代理、修改DNS/TLS/robots/配额、放行POST搜索、持久化登录、部署服务或改写高级批次和公开任务控制的历史受阻接线。
