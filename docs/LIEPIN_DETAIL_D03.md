# D03：已返回页面的岗位身份与正文提取

父任务 #49 / 专项 #46。实施基线 `c76057a470227dd1870f4a5d56099f302a53e74b`，已包含用户合并的 PR59。本文不是登录、搜索接口或实站采集已通过的证明。

## 本次代码直接作用于哪里

内置猎聘注册项改用 `LiepinAdapter` v3。原生/桥接后端返回页面后，沿用原 `GuidedService` 的列表 → 所选详情 → JobRecord → 原报告路径，不新增平行导入入口，不要求用户写 JSON 或复制 JD。已有原生登录窗口、登录后“继续原任务”及失败后保留成功正文的行为保持。

1. 列表岗位按平台、精确主机、URL 路径类型和岗位编号关联；跟踪参数不改变岗位实体标识；但完整保留原列表 Card.id 和顺序，包括跟踪链接变体，以兼容已保存的页签名与任务选择。本次不进行列表/跨页/历史任务去重迁移，实体去重留待D05。`job`、`a`、`lptjob` 三类路径不擅自合并为一个实体。
2. 落盘前核对所选 URL 和实际详情 URL 的岗位身份。详情跳到其他岗位，或 canonical 声明冲突，不保存为所选岗位正文。元数据 URL 只校验，绝不跟随请求。
3. 继续优先使用已有 JSON-LD / 独立正文容器解析。其后可读取一个明确标记为“职位介绍”的语义块：`dl/dt/dd` 或独立 `section/article/div` 中的标题和相邻正文。未知布局、多个可见标题、多个介绍、嵌套公司/推荐内容均明确失败；不会退回整个 body。
4. 需要展开/登录的正文标记为不完整；没有 AI 编程要求的完整正文仍可进入原研究报告，分析如实为零。
5. 成功项和本批审计增加平台岗位标识、解析器、适配器版本和正文 SHA256。未知公司/地区不填假值，诊断不增加正文或凭据。

这是对实际 `.cards()`、`.detail()` 和保存前检查的接线，不是未接入的解析函数库。通过代码回滚将该单站注册项恢复为原DOMAdapter，可回到原通用解析（未新增运行时开关）；历史工作区、报告和配额格式仍兼容。

## 实际证据与未验证范围

2026-09-18 本轮公开网页研究中，猎聘索引结果显示了职位标题和“职位介绍”文本；直接读取一份职位页面时转向 `safe.liepin.com` 的验证码页面，未获得成功的原始页面样本。robots 和关键词搜索页也未能由研究工具取得。此结果属于研究环境，不是用户本机或 Radar 原生后端的现场验收。停止该路径，不切换出口、UA 或工具重试验证码，不以搜索索引缓存当本批真实采集。

因此，上述语义 HTML 形态的回归全部是明确标记的合成页面，**不是声称已观测到当前猎聘 DOM 的所有形态**。适配状态保持 `not_live_verified`，没有增加猜测的搜索 API、登录 POST、CDN/SSO 白名单。仍需用户本机正常会话中的允许页面/必要依赖确认，才能完成 #49 的完整实站目标。没有私有账号或有效会话，就不能在此替用户完成平台二次验证。

参考公开页面：`https://www.liepin.com/job/1977446563.shtml`。这里只记录观察地址和失败类别，不把正文、验证码参数或招聘人员资料提交到仓库。

## 登录返回后自动接续（本次增量）

第3步新增默认不勾选的“本次登录返回原检索结果页后自动继续”。仍由用户在已有原生页面完成平台要求的正常登录/扫码；程序不填写密码，不提取Cookie，不重放登录请求。

勾选后，在同一工作线程上每秒至多观察一次当前页面，最长10分钟。只有页面与本任务原始列表地址和完整查询参数一致（允许既有规则剔除的跟踪参数）、连续两次识别到同一非空岗位列表时，才自动进入既有capture或继续所选岗位流程。暂停、停止、新动作、浏览器替换、超时和明确请求错误均终止观察；不会轮询站点API、刷新页面或扩大检索条件。正在填写登录表单时不操作页面。返回首页/其他查询/详情推荐区时继续等待，而非误采数据。

这证明当前列表可读，不是特定账号认证证据，也不是#50自动填写/持久会话已经完成。需要用户手动返回原检索页的网站仍需后续专用登录回跳适配；该增量不能取代尚缺的真实平台登录/CDN/搜索契约。

同时修复原生后端中同一未支持弹窗被浏览器根会话、父会话和页面事件重复同步关闭的竞争：由目标守卫去重关闭；页面事件只停止任务并记录待清理页面，不在window.open事件内再次同步close。页面未获准的控制结果不变，不开放弹窗/验证码或未知操作。Windows有界面此前在negative-popup停住的原始记录保留；必须在本次实际提交的四组原生CI复核，不能只凭本地单测宣布修复。

回归新增查询精确匹配、重复参数/改变过滤条件、取消与异常竞争、超时、自动接续现有报告，以及弹窗关闭去重和资源上限。现有浏览器验收保留默认人工返回流程，另用独立合成任务验证勾选后无需Capture/Resume点击；所有数据仍为明确标识的人工页面，不是猎聘实站认证。

### 首请求边界的实测修正

中途e7d246b的Windows反例证明：仅暂停目标并延后关闭，不能保证弹窗首个网络请求不发出；该候选未获合并认可，失败原样保留。修正增加在任何页面创建前安装的BrowserContext请求归属门：尚未绑定本应用CDP控制的页面、子frame或取消后的请求直接abort；已绑定主页面仅无参数continue，浏览器仍处理原HTTP/TLS/Cookie/压缩，没有fetch/fulfill和Python重发。原生CDP继续逐跳业务/配额控制，跨源preflight仍不属于当前支持契约。不得把这项归属门描述为完全不使用Playwright route；它不是原HTTP响应桥。

目标事件只负责停止和记录清理，实际关闭在所属工作循环执行，避免window.open同步回调死锁。首请求拦截和关闭是两层不同职责；真实浏览器仍必须证明所有/apply反例零请求及正常业务链通过，不能通过删除该断言获得绿灯。官方接口依据：https://playwright.dev/python/docs/api/class-browsercontext#browser-context-route 与 https://playwright.dev/python/docs/api/class-route#route-continue。
