# D03：已返回页面的岗位身份与正文提取

父任务 #49 / 专项 #46。实施基线 `c76057a470227dd1870f4a5d56099f302a53e74b`，已包含用户合并的 PR59。本文不是登录、搜索接口或实站采集已通过的证明。

## 本次代码直接作用于哪里

内置猎聘注册项改用 `LiepinAdapter` v3。原生/桥接后端返回页面后，沿用原 `GuidedService` 的列表 → 所选详情 → JobRecord → 原报告路径，不新增平行导入入口，不要求用户写 JSON 或复制 JD。已有原生登录窗口、登录后“继续原任务”及失败后保留成功正文的行为保持。

1. 列表岗位按平台、精确主机、URL 路径类型和岗位编号关联；同一返回列表内不同跟踪参数不再制造重复岗位；保留首条链接已有的 Card.id，兼容已保存的任务选择，不在本次进行历史卡片/跨页去重迁移。`job`、`a`、`lptjob` 三类路径不擅自合并为一个实体。
2. 落盘前核对所选 URL 和实际详情 URL 的岗位身份。详情跳到其他岗位，或 canonical 声明冲突，不保存为所选岗位正文。元数据 URL 只校验，绝不跟随请求。
3. 继续优先使用已有 JSON-LD / 独立正文容器解析。其后可读取一个明确标记为“职位介绍”的语义块：`dl/dt/dd` 或独立 `section/article/div` 中的标题和相邻正文。未知布局、多个可见标题、多个介绍、嵌套公司/推荐内容均明确失败；不会退回整个 body。
4. 需要展开/登录的正文标记为不完整；没有 AI 编程要求的完整正文仍可进入原研究报告，分析如实为零。
5. 成功项和本批审计增加平台岗位标识、解析器、适配器版本和正文 SHA256。未知公司/地区不填假值，诊断不增加正文或凭据。

这是对实际 `.cards()`、`.detail()` 和保存前检查的接线，不是未接入的解析函数库。关闭该单站新适配后可回到原通用解析；历史工作区、报告和配额格式仍兼容。

## 实际证据与未验证范围

2026-09-18 本轮公开网页研究中，猎聘索引结果显示了职位标题和“职位介绍”文本；直接读取一份职位页面时转向 `safe.liepin.com` 的验证码页面，未获得成功的原始页面样本。robots 和关键词搜索页也未能由研究工具取得。此结果属于研究环境，不是用户本机或 Radar 原生后端的现场验收。停止该路径，不切换出口、UA 或工具重试验证码，不以搜索索引缓存当本批真实采集。

因此，上述语义 HTML 形态的回归全部是明确标记的合成页面，**不是声称已观测到当前猎聘 DOM 的所有形态**。适配状态保持 `not_live_verified`，没有增加猜测的搜索 API、登录 POST、CDN/SSO 白名单。仍需用户本机正常会话中的允许页面/必要依赖确认，才能完成 #49 的完整实站目标。没有私有账号或有效会话，就不能在此替用户完成平台二次验证。

参考公开页面：`https://www.liepin.com/job/1977446563.shtml`。这里只记录观察地址和失败类别，不把正文、验证码参数或招聘人员资料提交到仓库。
