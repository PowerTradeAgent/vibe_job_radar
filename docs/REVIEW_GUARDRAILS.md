# 历史报告兼容与凭据隔离

本说明补充 `WORKFLOWS.md`，对应 PR #6 的四项审查修复。

## 冻结配置与证据范围

能力选项与保存校验以所选来源报告的冻结配置为准，而不是后来安装的配置。个人报告只使用明确关联该来源报告的证据与复核；其他报告证据保留在资料库，不默默混入。`evidence_revision.json` 记录排除的其他报告证据数。要让已有证据用于另一个来源报告，应在界面中明确编辑并重新映射。

## 提取规则兼容性

提取规则版本不兼容时拒绝生成，并要求显式重新分析、复核和映射。即使版本号未变化，也比较重新提取的完整要求集合与冻结要求的 ID、引用、分类、强度、工具及岗位语义；不一致则撤销本次尚未交付的输出，不生成映射失效的个人报告。

历史 LLM 提案无法按当前引擎复现时同样需要显式重新分析。旧报告不修改，已有证据版本不删除。该门控用于避免软件升级后静默改变已经复核的招聘要求。

## 按模式选择凭据

CLI 根据任务模式选择凭据：搜索只读取 `BRAVE_SEARCH_API_KEY`，授权数据源只读取 `RADAR_FEED_TOKEN`，URL 路线不带服务凭据。同时配置两种环境变量不会互相代用。

API、契约与外部证据 URL 拒绝 `key`、`sig`、`signature`、`credential`、`token` 等常见查询式认证参数。带认证的服务应使用请求头，不将密钥放进持久化的 URL。此检测不替代用户检查内容和本机凭据管理；项目不声称可以从任意自由文本中识别所有秘密。

## 回归验证

`tests/test_final_review.py` 增加十项独立测试，覆盖当前/历史能力不一致、其他报告证据隔离、提取版本变化、未更新版本号的语义变化、两种环境凭据同时存在，以及签名 URL 在持久化前被拒绝。完整测试数从 166 增至 176，最终通过情况以 PR 最后提交的 CI 为准。
