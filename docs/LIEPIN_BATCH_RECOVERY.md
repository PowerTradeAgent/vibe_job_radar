# 猎聘批次与恢复进展（#51 / #52）

## 已实现的有限分页

新任务保存 `identity_strategy=platform_entity_v1`。列表卡片按适配器验证过的
平台实体去重，保留首次观察到的实际导航链接。猎聘的主机、`job` / `a` /
`lptjob` 路径族与职位编号共同组成实体；不假设不同路径族或主机互为别名。
跟踪参数变化不增加本批岗位数，不会据此构造新的请求 URL。

新任务的页面签名与卡片顺序无关。分页明确记录 `repeated_page`、
`no_new_entities`、`no_next_button`、`confirmed_empty`、`page_limit` 或
`card_limit`。后续空页不会抹去先前发现的岗位，也不再把整个批次说成零结果。
每批仍最多 5 页、100 张候选卡片、20 个选中岗位。

没有 `identity_strategy` 的旧任务继续使用已有 URL 卡片 ID 和顺序签名，
不改写旧选择或已保存结果。未知策略明确停止，不静默使用另一套身份规则。
这是批次内去重；尚未改变全局 Store 的历史记录身份或证明跨任务增量同步。

## 验证边界

`test_guided_batch_identity.py` 使用明确的合成多页列表，覆盖参数变化、
跨页重复、重排、子集页、页面与卡片上限、不同路径族、旧任务和重载后的选择。
本轮相关 171 项测试通过。它们不是真实岗位样本，不满足 #54 实站验收。

真实列表和首条完整 JD 仍受 #63 的主页面空白问题阻塞；未完成实站分页认证。
