# 采集表单到底怎么填：从字段来源到第一份结果

你已经启动成功、能看到 `/advanced` 时，不需要再安装 Python。问题是选路线和取得输入，并不是要把页面里的所有空格都填满。

新版高级页会根据路线隐藏无关字段，并提供“检查填写 / 预览计划（不采集）”。预检只请求本机程序，外部网络请求为 0，不保存任务，也不证明 Key 有效或网站允许采集。

## 先按你手上有什么来选择

| 你现在有什么 | 应选择什么 | 不需要准备什么 |
|---|---|---|
| 已经找到一个具体职位详情页 | 职位 URL 列表 | 不要申请搜索 Key；不填数据源地址和契约 |
| 希望程序先找出招聘链接 | 搜索 API | 不需要先准备职位 URL；不填数据源地址和契约 |
| 数据供应方已经给了接口和文档 | 授权 JSON 数据源 | 这不是普通求职用户必需的路线 |
| 只有 App 里的 JD 文本，没链接也没 Key | 返回基础页，粘贴 JD | 无需任何 API 或平台账号托管 |

**第一次建议只选一个岗位和一个平台。** 后续可以再扩大范围。入门参数按钮不会创建任务，不会填造假的 Key、职位或授权，也不会替你勾选同意。

## 案例 A：已经有一个 BOSS 职位，URL 路线怎么填

### A1. 职位 URL 去哪里找

在浏览器打开 [BOSS直聘](https://www.zhipin.com/)、[猎聘](https://www.liepin.com/) 或 [前程无忧](https://www.51job.com/)。这些链接只是找职位的入口，**不要把首页直接填入表单**。

在你自己的客户端正常搜索“时间序列算法工程师”，点进一条具体职位，确认能看到职位名称、公司和职责。点击浏览器地址栏，或按 `Ctrl+L`，再按 `Ctrl+C` 复制，回表单粘贴。多个职位一行一个；第一次只用一条。

App 的“分享 / 复制链接”也可尝试，但必须能在浏览器打开对应的职位。只有小程序口令、短链无法展开或没有网页地址时，改在基础页粘贴有权处理的完整 JD。不要自己拼造职位 ID。

格式示意，**不能直接提交**：

```text
https://www.zhipin.com/job_detail/REPLACE_WITH_REAL_JOB_ID.html
```

`REPLACE_WITH_REAL_JOB_ID` 必须来自你实际打开的职位 URL。程序会将这类占位符识别为示例，而不是拿它尝试抓取。

不要填：招聘首页、职位列表页、`http://127.0.0.1:53892/advanced`、`D:/xxx` 文件路径、登录链接、Cookie、完整的聊天分享口令或搜索 API 地址。本机端口只用于工作台，不是招聘数据地址。

### A2. 逐格填写

点击“我有职位链接：套用 URL 入门参数”，按下面核对：

| 当前字段 | 本案例填写 | 从哪里取得 / 为什么 |
|---|---|---|
| 目标岗位 | 时间序列算法工程师 | 选择你要研究的岗位，按实际标题选择，不要改造原文 |
| 检索 / 数据源平台 | BOSS直聘 | 与你复制链接的真实域名对应；也可点“从链接识别来源平台” |
| 采集路线 | 职位 URL 列表 | 已有链接，不必用搜索服务找链接 |
| 职位 URL 列表 | 粘贴一条自己实际打开的完整 HTTPS 职位地址 | 地址栏 / 可打开的分享链接；不是上面的示例文本 |
| 正文获取尝试预算 | `1` | 第一次只尝试一条，避免批量碰到同一个问题 |
| 复用已采集正文的时间窗口 | `24` | 24小时内已有合格正文时可优先复用 |
| 实际授权依据与使用范围 | 写自己的真实来源、允许使用依据和用途 | 不是再找一个 API Key，也不是一句“我同意”就取得权限 |
| 正文访问许可 | 确有依据时才勾选 BOSS直聘 | 仅“浏览器能打开”不等于程序自动访问获准 |
| 执行确认 | 核对后本人勾选 | 参数按钮不会自动勾选 |

**Key / Token、搜索预算、检索页数、数据源地址、契约、数据源页数、搜索结果保存权限均不属于 URL 路线，不用填。**

授权说明结构参考（仅在实际成立时填写；括号不是可直接使用的文本）：

> 来源为【具体职位页面或接口】；依据【实际适用的访问条款或提供方授权】；用于本人岗位要求研究，本次最多取得1条职位，不公开转发原文。

这个字段没有一串“万能授权码”可以申请。依据可能是适用的接口/页面访问说明、数据提供方给出的使用许可，或你自己有权管理的数据源。没有依据就不要编造，回到基础页输入有权处理的文本即可。

点击“从链接识别来源平台”只会识别域名、勾选来源，**不会勾选正文许可**。

### A3. 先检查，再执行，最后看什么

点击“检查填写 / 预览计划（不采集）”。有错误时逐条补齐：比如“URL 列表为空”“这是首页”“尚未确认正文访问许可”。没有错误后，明确点击“创建并自动执行”。

成功获得正文时，任务逐条结果出现 `ok`；如果复用已有新鲜正文，会是 `fresh_reused`。下载逐条要求 CSV，并核对原文。即使正文获取成功，也不保证该职位一定包含 Vibe Coding 要求。

遇到 `login_or_challenge`、`http_403`、`robots_disallowed`、`parse_error` 等状态，不代表你一定填错了。当前实现不会执行目标网页 JavaScript，也不会复用你浏览器里的登录会话。不要为了让结果变绿反复加预算或编造许可；查看具体失败原因，必要时改用基础页粘贴正文。

## 案例 B：没职位 URL，希望程序找链接，搜索路线怎么填

### B1. Search API Key 去哪里拿

官方入口：[Brave Search API 控制台](https://api-dashboard.search.brave.com/)。官方操作说明：[Quickstart](https://api-dashboard.search.brave.com/documentation/quickstart) 和 [Authentication](https://api-dashboard.search.brave.com/documentation/guides/authentication)。以下步骤于 2026-09-14 核对，页面标签/套餐以后可能变化。

1. 注册或登录自己的 API 账号，验证邮箱。
2. 在 `Plans` 中启用支持 Web Search 的 `Search` 套餐；官方当前指引要求按提示提供支付资料。核对价格、用量上限和保存结果权限，不能只依据旧教程认为永久免费或无限量。
3. 到 `API Keys`，点击 `Add API Key` / 创建密钥。名称可写 `vibe-job-radar`。
4. 复制控制台生成的 Key，回高级页粘贴到 `Brave Search API Key`。

这里不需要编程、不需要手工调用 API。**填的是密钥值，不是邮箱密码、BOSS 密码、搜索 API 网址，也不是大模型服务的 Key。** 名称 `vibe-job-radar` 只是控制台中方便你识别的备注，也不是要填入程序的密钥。

不要把 Key 发给聊天或贴到 Issue。页面输入法仅本次进程操作使用；当前启动环境已经设置 `BRAVE_SEARCH_API_KEY` 时可以留空沿用环境变量，但仅“发现已配置”不证明 Key 有效。不使用环境变量也能操作，无需改源码或重启来填写表单 Key。

### B2. 先只获取搜索线索，避免同时调试详情采集

点击“我想先搜索：套用搜索入门参数”，然后填写：

| 当前字段 | 本案例填写 | 解释 |
|---|---|---|
| 目标岗位 | 时间序列算法工程师 | 系统据配置组合检索词，不需要自己写 API 查询表达式 |
| 检索 / 数据源平台 | BOSS直聘 | 先1个平台，之后可增加猎聘、前程无忧 |
| 采集路线 | 搜索 API | 通过搜索服务发现标题、链接和摘要 |
| Brave Search API Key | 自己刚刚在控制台复制的 Key | 不能把示例 `YOUR_API_KEY` 当成有效值 |
| 搜索请求预算 | `1` | 最多调用搜索 API 1次，不是“恰好1个岗位” |
| 每个检索任务最多页数 | `1` | 第一次不翻多页 |
| 正文获取尝试预算 | `0` | 只搜摘要，不访问招聘网站详情页 |
| 实际授权依据与使用范围 | 按下面的真实用途参考句填写 | 搜索保存用途，不是假称平台授权 |
| 搜索结果保存权限 | 仅确认自己的套餐与用途允许后勾选 | 未核对时不要盲目勾选 |
| 执行确认 | 核对后本人勾选 | 明确同意按预算执行 |

用途参考句（必须符合自己实际情况）：

> 个人求职研究；仅保存本人套餐允许保存的搜索结果；本次只获取标题、链接和摘要，不自动访问招聘网站详情正文。

**职位 URL 列表、数据源地址、契约链接、数据源最大页数不用填；正文预算为 0 时不需要勾选正文访问许可。**

点击“检查填写 / 预览计划（不采集）”即可看到系统准备的检索词。没有 Key 时仍能看计划，但会提示缺 Key，不能执行真实搜索。预览计划本身不是请求第三方搜索服务。

### B3. 执行后应该期待什么

只有明确点击“创建并自动执行”才开始外部调用。可检查本次搜索请求数、每个检索任务的 `results_seen` / `leads_stored`、基础页的摘要计数和任务详情。

这组入门参数**故意不会取得完整 JD**，也就不会凭空生成完整正文要求统计。由于预算只执行部分查询、没有正文，任务可能显示 `needs_attention` 或 `empty`；请分别看搜索是否返回了线索、哪些因预算未执行，不要把总体状态等同于 Key 一定错误或市场完全没有相关职位。

错误处理：401/403 检查服务 Key 与授权；429 检查额度/限流并停止反复提交；0条结果可能是索引、岗位或关键词问题。真实 Key、服务可达性和结果数量只能由执行请求验证，填写预检不做这些认证。

取得链接后，你再在许可范围内补完整 JD：可走 URL 路线，也可自行打开后在基础页粘贴。Search API Key 不能解锁招聘平台的登录墙。

## 案例 C：数据源地址和契约到底由谁给

这两项只属于“已获授权的 JSON 数据源”路线。需要向真正的数据提供方索取：一个可用的 HTTPS JSON 接口、接口/授权说明、必要的只读 Token 和允许使用范围。并确认返回结构符合项目 `jobs` / `next_cursor` 契约。

没有供应方接口的普通求职用户直接忽略这条路线，不用去寻找一个“所有招聘网站通用 API”，也不要把招聘首页或 Brave API 地址填成授权职位数据源。详见 [数据源契约](WORKFLOWS.md)。

## 更新页面时不用换 Python 环境

该修改无新增运行依赖。继续使用你已经成功的 `python.exe scripts/start_workbench.py` 启动命令。PR 未合并前要下载/切换到对应 PR 分支，不是反复下载旧 main。

完整解压新源码到新目录，先停止旧终端中的工作台进程（Ctrl+C），进入新源码目录后再用原 Python 解释器启动。打开这次终端给出的完整带令牌地址，再进入高级页；端口可能不同。仅刷新浏览器不会把旧 Python 进程换成新代码。

默认工作区与源代码目录分开，更新前仍建议在停止服务后备份整个工作区。不要删除数据目录来“刷新页面”。原有本地演示、证据表单与 CLI 保留，本文不宣称新增平台专用爬虫。
