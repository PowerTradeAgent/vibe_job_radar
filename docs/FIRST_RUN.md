# 零基础操作指南：从下载到第一份真实报告

首次目标只有一个：在自己的电脑打开工作台，录入一条有权处理的真实职位描述并下载报告。先不配置任何爬虫账号、搜索密钥或模型。JD 就是招聘方写出的“岗位职责 + 任职要求”。


## 已经打开过工作台：直接更新，不要重装环境

已经使用 Anaconda/Python 成功启动的人，跳过第1节。先在旧终端按 Ctrl+C，停止后备份页面显示的完整数据目录（默认用户主目录下 `.vibe-job-radar`）。然后从 GitHub 的 **main → Code → Download ZIP** 下载并解压新源码；不要继续运行旧解压目录。

进入新源码目录，沿用你已经成功的解释器。例如在 Git Bash 中使用现有 Anaconda 环境：

```bash
/d/code_environment/anaconda_all_css/py312/python.exe scripts/start_workbench.py
```

这是本项目用户已验证可用的解释器路径示例，不要求其他电脑创建同名目录。路径不相同的用户使用自己的 Python；含空格时给解释器完整路径加引号。使用同一工作区即可保留原有数据，不要为了更新删掉数据库。

打开本次终端给出的完整地址，再点首页的“进入自动采集 / 原文复核 / 附件与量化指标工作台”。不要沿用旧端口书签。看到下面三个入口即表示新的填写指引已经加载：**我有职位链接：套用 URL 入门参数**、**我想先搜索：套用搜索入门参数**、**检查填写 / 预览计划（不采集）**。若看不到，检查运行目录与旧进程，而不是反复安装 Python。

## 已进高级页但不知道怎么填：只选一条路线

| 你手上已有的东西 | 点哪个入口 | 第一轮填什么 | 不用填什么 |
|---|---|---|---|
| 一条具体职位详情链接 | 我有职位链接：套用 URL 入门参数 | 1岗位、1平台、真实链接1条、正文预算1、复用24小时；按实际依据确认访问范围 | 搜索 Key、JSON 接口、契约、搜索预算 |
| 想让程序帮忙找职位链接 | 我想先搜索：套用搜索入门参数 | 自己的 Brave Key、1岗位、1平台、搜索预算1、页数1、正文预算0；核对搜索保存范围 | 事先整理的职位 URL、JSON 接口、正文许可 |
| 数据供应方给了接口和文档 | 授权 JSON 数据源 | 公网 HTTPS 接口、契约链接、必要的 Token、允许范围 | 不要拿招聘首页或搜索接口代替职位数据源 |
| 只有 JD 文本，没链接也没 Key | 返回基础工作台 | 粘贴一条有权处理的完整 JD，保存再分析 | 一切搜索/数据源凭据 |

**网址从哪里来：** 自己在招聘网站点进具体职位，Ctrl+L、Ctrl+C 复制地址栏。不是首页、搜索列表、本机 `/advanced` 或示例职位ID。**Key从哪里来：** 从 [Brave 官方控制台](https://api-dashboard.search.brave.com/) 按其现行步骤开通 Search 并创建 API Key，填生成的密钥值，不是账户密码、密钥名称或网址。**接口从哪里来：** 由实际数据提供方给出；没有供应方时忽略该路线。

点击入门参数后仍需自己填真实输入，按钮不会自动填授权、密钥或职位，也不会自动联网。先点“检查填写 / 预览计划（不采集）”，按字段提示补齐，再由你点“创建并自动执行”。预检不消耗外部 API 请求，也不验证网站可抓、密钥有效或授权成立。没有 Key 仍能预览计划，但不能发起搜索。

搜索预算1不是只返回1条职位；正文预算0会**故意只得到标题、链接和摘要**，不能据此生成完整正文要求统计。遇到 empty/needs_attention 先查看具体请求与结果，不要马上提高预算。详细的逐格表、真实用途填写参考与错误对照见 [采集表单案例](COLLECTION_FORM_CASES.md)。

恢复历史任务时，已进入正文/报告阶段的搜索任务无需再填 Brave Key。切换到数据源历史任务时先暂停让你填写该数据源 Token；只有提供方明确无需 Token 才可再次点击并确认无 Token 继续。程序不会复用上一种服务的密钥，也不会自动重试已经结束的任务。

## 1. 准备 Python（已有 3.10+ 可跳过）

Python 是运行本程序的软件环境。本项目不是独立 EXE；只安装浏览器还不够。当前跨平台 CI 测过 3.10、3.11、3.12，建议首次验证选 3.12。

**Windows：** 从 [Python 官方下载页](https://www.python.org/downloads/) 获取 Python Install Manager 并安装。按 Windows 开始菜单，搜索“PowerShell”并打开，在窗口中粘贴下列命令，按回车：

```powershell
pymanager install 3.12
py -3.12 --version
```

第一条需要联网安装 Python。第二条应输出 `Python 3.12.x`。`pymanager` 是新版官方安装管理器命令；只有旧版 `py` 的电脑不能直接用它安装，应先安装官方管理器。已安装合适 Python 的电脑不必卸载或重装。多版本并存时，用下面固定版本的启动命令，避免双击入口选择了别的默认版本。

**macOS：** 从官方页面选择 macOS 安装包，按安装器步骤完成。打开“终端”，输入 `python3 --version`；输出须不低于 3.10。需要严格对应 CI 时选用 Python 3.12，并以 `python3.12` 启动。**Linux：** 用发行版支持的方式安装 Python 3.10+，在终端用同一命令确认版本。不要覆盖系统 Python。

安装方式核对自 [Python Windows 官方说明](https://docs.python.org/3/using/windows.html)，核对日期 2026-09-14。命令不存在时先解决 Python 安装，不要反复双击项目。

## 2. 下载完整 main，而不是单个脚本

用有仓库访问权限的账号打开 [项目仓库](https://github.com/saksim/vibe_job_radar)。左上方分支选择 `main`，点击绿色 **Code → Download ZIP**。若是私有仓库，看不到内容时需要仓库所有者授予权限；安装 Python 不能解决 GitHub 权限问题。

在下载目录找到 ZIP，右键“全部提取/解压”，打开解压后的项目文件夹。应同时看到 `README.md`、`start_windows.bat`、`START_HERE.html`、`scripts`、`src`、`docs`。**不要在压缩包预览窗口里启动，也不要只下载一个 .py 文件。**

解压后双击 `START_HERE.html` 可用浏览器阅读入门卡。它只是文档，打开它不会启动工作台。

## 3. 启动，识别两个窗口

Windows 单一 Python 环境可双击 `start_windows.bat`。固定 Python 3.12 的操作：在项目文件夹的地址栏输入 `powershell` 并回车，在出现的窗口运行：

```powershell
py -3.12 scripts/start_workbench.py
```

macOS/Linux：在终端输入 `cd `（注意尾部空格），拖入解压后的项目文件夹得到实际路径，回车，再运行：

```bash
python3 scripts/start_workbench.py
```

应出现两个窗口：终端显示“本地工作台”和“数据目录”；浏览器显示“招聘要求 → 逐条证据 → 可量化描述”。终端负责运行程序，**不要关闭它**。浏览器只是操作界面。

浏览器没自动打开时，复制终端整条地址，包括 `#token=...`，粘贴到本机浏览器地址栏。用启动器给出的 `127.0.0.1`，不要换成 `localhost`，不要把令牌地址给别人。默认端口每次可能不同，所以旧书签不一定可用。

点击“环境自检（不联网）”。成功标志是返回 `workspace_writable: true`，且没有错误。`network_tested: false` 正常：自检并未测试招聘平台和密钥。

## 4. 先认识报告，再录入真实文本

点击“运行合成演示”。应看到“合成演示”、要求行和文件下载按钮；真实记录仍为 0，说明演示隔离正常。演示只用来认识界面，不能作为真实招聘统计。

随后在你自己的招聘网页或 App 找到一条目标岗位。需要登录时在该网站/App 正常登录。本项目不读取那个浏览器的 Cookie。确认有权处理内容后填写：

| 界面字段 | 填写方法 | 避免的错误 |
|---|---|---|
| 职位名称 | 招聘方的实际标题 | 不要把无关岗位改名为“架构师”来制造匹配 |
| 来源平台 | 与原链接对应的平台；其他来源选手工来源 | BOSS 链接不能选猎聘 |
| 招聘公司、城市 | 知道就填，不知道留空 | 不推测公司 |
| 职位来源链接 | 职位分享链接，不带账号凭据 | 不贴后台 Token 或 Cookie |
| 来源说明 | 无链接时填写可追溯说明 | 不凭空编一个网页地址 |
| 原始岗位职责与任职要求 | 保留完整正文和段落 | 不混入聊天、其他人的简历或联系方式 |
| 证据完整性 | 完整 JD 选完整正文；片段选摘要 | 搜索摘要不能升级为完整 JD |
| 来源与允许使用范围 | 实际来源、许可依据和使用目的 | 文字声明本身不是取得授权 |

完整正文须勾选完整性确认，再点“保存到真实数据库”。成功标志：提示已保存，记录数增加；重复相同内容时可能只增加观察、不增加快照。若岗位未匹配，核对原始标题和岗位配置，不要伪造职位名称。

## 5. 生成第一份真实报告

在“选择岗位与发现线索”中勾选对应岗位，然后点“分析真实数据并生成报告”。基础页面的平台复选框影响搜索发现；其分析按钮按岗位筛选现有数据。高级采集任务则还按所选平台筛选。

检查报告模式不是合成演示，`正文岗位组` 至少为 1。确有 Vibe Coding 正向要求时应有对应原文行；合法的零命中也可能存在，不能为了有结果编造要求。

先下载 `requirements_zh.csv`，在 Excel 中查看逐条原文；下载 `descriptions.md`、`role_descriptions.md` 和 `evidence_gaps.md` 查看描述及缺口。`.md` 是文本，可用记事本打开；下载 `dashboard.html` 后可用浏览器查看静态报告。当前不是 XLSX 输出。

文件通常在浏览器下载目录；程序也把完整报告保存在界面显示的数据目录的 `reports/` 子目录。每次分析产生新目录，不覆盖旧报告。

## 6. 再做自己的证据，自动采集不是前置条件

从首页点“进入自动采集 / 原文复核 / 附件与量化指标工作台”。已有真实报告时，可直接跳过第一部分采集，使用第二至四部分：

选择刚才的真实报告 → 加载原文要求 → 复核此条 → 勾选证据支持的要求 → 填项目与本人负责范围 → 上传附件或填写外部引用 → 添加真实指标 → 保存个人证据 → 生成个人报告。

“校验并预览”不会自动保存指标；还要点“添加到当前证据”，最后点“保存个人证据”。只有真实证据充分时才选“本人已确认”，否则保存草稿。详见 [采集与证据操作指南](WORKFLOWS.md)。

## 7. 自动采集什么时候配置

三条采集路线都在高级页：搜索路线需自己的 Brave Key 与相应存储权限；URL 路线需要真实链接与允许的访问范围；数据源路线需要实际符合约定的 JSON API。**都不等于自动登录各大网站。** 首次建议只选一个平台、一个岗位、小预算，先看正文是否取得，再扩大范围。

没有 Key、API 或允许自动访问的页面时，录入和证据分析仍可用。不要为了得到结果，随意勾选没有依据的许可。详细字段、凭据和限制见 [WORKFLOWS.md](WORKFLOWS.md) 与 [采集能力说明](ACQUISITION_CAPABILITIES.md)。

## 8. 常见问题对照

| 现象 | 先检查什么 / 怎么操作 |
|---|---|
| 提示 Python 不存在 | 确认安装完成，重新打开终端，检查 `py -3.12 --version` |
| 报 `can't open file` | 当前目录不对；应看到 scripts 和 src 文件夹后再启动 |
| 双击一闪而过或停在错误 | 在项目目录用固定版本命令启动，阅读错误；不要关闭安全软件 |
| 403、令牌无效 | 从本次终端重新复制完整地址，先打开基础页再进入高级页 |
| 地址连不上 | 终端是否还在运行；是否打开了旧端口；是否在另一台电脑访问 |
| 目录不可写 | 加 `--workspace` 指向自己的可写目录；不要用只读系统目录 |
| `permission_required` | 该来源没有在任务中获得正文访问许可；不是账号密码错误 |
| `robots_denied` / `robots_unavailable` | 当前实现停止自动访问；不可用包括 404，这是保守实现，不是法律结论 |
| `login_or_challenge` / 403 / 429 | 网站要求登录、验证或限制访问；当前程序不绕过，转授权渠道或手工输入 |
| `redirect_not_followed` | 当前不自动跳转；核对有权访问的最终职位 URL 后创建新任务 |
| `parse_error` / `not_html` | 不是可识别的独立 JD；普通网页、推荐列表、动态页面不一定可解析 |
| `invalid_feed_contract` | API 不是约定 JSON 结构或字段不合法；不是任意网址都能当数据源 |
| 零正文 / 零要求 | 检查摘要、岗位、采集新鲜度、否定条款、input_audit.csv 与 review_queue.csv |
| 证据版本冲突 | 刷新资料，核对其他标签页的修改后再保存，不强行覆盖 |
| 指标预览有值但报告无指标 | 是否添加到当前证据、保存为已确认、选中了同一来源报告 |
| 历史规则不兼容 | 重新分析，并重新复核/映射；系统不会偷偷重用已失效要求 |

出现错误时，保留不含密钥的错误文字、Python 版本和操作步骤。不要把登录令牌地址、账户凭据或含个人数据的完整工作区贴进 Issue。

## 9. 停止、升级、备份

在终端按 Ctrl+C 停止。Windows 启动器最后可能显示“按任意键继续”，此时服务已经结束。关闭浏览器不等于关闭本地服务；高级页关闭后不会驱动后续采集步骤，但已经发出的请求可能完成。

默认数据目录：Windows 是 `%USERPROFILE%\.vibe-job-radar`，macOS/Linux 是 `~/.vibe-job-radar`；以工作台显示的实际路径为准。里面保存 jobs.sqlite、demo.sqlite、reports、imports、collections、evidence 等。**停止服务后备份整个目录**，不要只复制主 SQLite 文件而遗漏相关文件。

升级时：停止服务 → 备份数据目录 → 把最新 main 源码解压到新的程序目录 → 以原来的 `--workspace` 启动 → 自检和查看历史。不要拿空演示目录覆盖真实数据。

撤回证据不删除旧报告和审计历史；要彻底清理本机记录，先停止并备份，再处理整个工作区。个人证据 ZIP 是证据导出，不是包含全部 JD/数据库/任务状态的整机备份，也不是浏览器一键恢复格式。源码ZIP与数据备份是两件不同的事。
